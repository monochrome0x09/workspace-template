# Task Lifecycle

작은 작업이 아닌 작업에 적용합니다. 작은 작업의 기준은 `AGENTS.md`의 Tasks에 있습니다.

TASK.md에는 항상 하나의 작업만 둡니다.

작업을 시작하면 코드나 문서를 바꾸기 전에 TASK.md를 먼저 채우고, 그 변경만 따로 커밋·푸시합니다. 이 푸시가 끝나기 전에는 다른 파일을 수정하지 않습니다.

## 여러 스레드

여러 스레드가 동시에 일할 때는 TASK.md 하나를 공유하지 않습니다. 이미 채워진 TASK.md가 있으면 덮어쓰지 말고 사용자에게 확인하거나 `docs/tasks/` 아래에 스레드별 파일을 씁니다. 사용자가 응답할 수 없는 상황이면 확인하지 않고 바로 `docs/tasks/` 파일을 씁니다.

`docs/tasks/<스레드 이름>.md`는 TASK.md와 같은 형식으로 작성하고, 위의 시작 절차와 완료 절차(결과 커밋과 분리한 삭제 커밋)를 그대로 따릅니다. 삭제 전에 장기 보존할 내용은 STATE.md 또는 `docs/decisions/`에 옮깁니다.

## 정리

- 완료한 작업 중 장기 보존이 필요한 내용은 초기화 전에 STATE.md(Completed/Recent Changes) 또는 `docs/decisions/`에 옮깁니다.
- 새 작업 요청 시 이전 작업 내용이 TASK.md에 남아 있으면 먼저 정리합니다.
- 초기화 전에 사용자에게 보존 여부를 확인할 필요는 없으나, 미완료 작업이 남아 있으면 확인합니다.
